# ⚡ Billing Automation

Инструмент для автоматического распределения лицензий IT-сервисов по ЦФО (центрам финансовой ответственности) с хранением в PostgreSQL и историей по месяцам.

---

## Быстрый старт

```bash
# 1. Создать виртуальное окружение и установить зависимости
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2. Настроить подключение к БД
cp .env.example .env
#   и отредактировать .env под свою PostgreSQL (host, port, имя БД, пользователь, пароль)

# 3. Создать таблицы и наполнить справочник сервисов
.venv/bin/python migrate.py

# 4. Запустить приложение
.venv/bin/streamlit run app.py
```

Приложение откроется в браузере по адресу `http://localhost:8501`.

### Требования

- Python 3.8+
- PostgreSQL (локально или на сервере), база данных создаётся заранее
- Библиотеки: `streamlit`, `pandas`, `openpyxl`, `psycopg2-binary`, `python-dotenv` (из `requirements.txt`)

### Настройка БД (`.env`)

Параметры подключения берутся из файла `.env` (в git не попадает). Шаблон — `.env.example`:

```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=billing_app
DB_USER=postgres
DB_PASSWORD=postgres
```

Саму базу нужно создать заранее (например `createdb billing_app`), а таблицы внутри неё создаст `migrate.py`.

## Периоды (отчётные месяцы)

Все данные привязаны к **периоду** (месяцу). Период управляется в блоке **🗓 Период** в боковой панели:

- **Создать период** — указать месяц (`YYYY-MM`). При создании цены и доп-пользователи копируются из предыдущего периода.
- **draft** — рабочее состояние: можно загружать файлы, менять цены и назначения.
- **Финализировать** — закрыть период: он становится **только для чтения**. Если загружены не все сервисы — будет предупреждение (не блокировка).
- **Вернуть в draft** — снова открыть финализированный период для исправлений.

> Нельзя создать новый период, пока есть незавершённый (не финализированный).

## Как работать

### 1. Загрузка файлов (боковая панель)

Сначала выбери или создай период, затем загрузи файлы:

- **Справочник сотрудников** — файл `Список_сотрудников.xlsx` из 1С (лист `TDSheet`). Ник — столбец A (с очисткой старых ников в скобках), ЦФО — столбец C (если пустой, подставляется «ПП НЕО»), подразделение — столбец B.
- **Файлы сервисов** — выгрузки из каждой системы, своё поле на каждый сервис.

После загрузки файл сразу парсится и записывается в БД для выбранного периода.

### 2. Вкладка «📊 Отчёт»

- **Статистика** — сотрудники в справочнике, число ЦФО, загруженные сервисы.
- **Ненайденные пользователи** — раскрывающийся блок с никами, которых нет в справочнике. Фильтр по сервису, массовое назначение ЦФО и индивидуальное назначение.
- **Кнопки генерации**:
  - **📊 Сформировать** — строит отчёт во вкладках прямо в приложении.
  - **⬇️ Excel (общий)** — тот же отчёт в `.xlsx`.
  - **📁 По отделам (ZIP)** — архив с папкой на каждый ЦФО (HTML + XLSX для финансов).

### 3. Вкладка «📈 История»

Аналитика по всем периодам:

- **Доходность сервисов** — графики и таблица стоимости лицензий по месяцам (общая и по сервисам), плюс количество лицензий.
- **Потребление по ЦФО** — таблица «месяц × ЦФО» с переключателем «Лицензии / Стоимость».

### 4. Вкладка «⚙️ Параметры»

- **Цены за лицензию** — поля для каждого сервиса (₽), сохраняются в БД для текущего периода. В финализированном периоде — только чтение.
- **Тема оформления** — light / dark / accent (применяется к интерфейсу и HTML-отчётам).

### 5. Вкладка «👥 Доп DB Users»

Таблица вручную назначенных пользователей текущего периода с привязкой к сервисам. Можно очистить все назначения.

## Поддерживаемые сервисы

| Сервис | Формат | Откуда берётся ник |
|--------|--------|--------------------|
| Google Workspace | CSV / XLSX | Столбец B (`Last Name [Required]`) |
| Miro | CSV / XLSX | Последнее слово из столбца A (`Name`) |
| GitHub | XLSX (1-я вкладка) | Столбец F (`GitHub com saml name ID`), фоллбэк на столбец A (`login`) |
| GitHub Copilot | XLSX (2-я вкладка) | Столбец C (`SAML Name ID or Email`) |
| M365 | XLSX (вкладка `Licenses by user`) | Последнее слово из столбца A (`User`), фильтр SKU = `SPE_E3` |
| Power BI | XLSX (вкладка `Licenses by user`) | Последнее слово из столбца A (`User`), фильтр SKU = `POWER_BI_PRO` |
| Mattermost | CSV / XLSX | Столбец A (`NickName`) |
| TestIT | CSV / XLSX | Столбец A (`Nickname`) |
| 1С Лицензии | XLSX | Столбец A (`ФизЛицо`) с очисткой скобок |
| Jira + Confluence | XLSX | Столбец A (`ФизЛицо`) с очисткой скобок |

### Добавление нового сервиса

Парсеры живут в коде (не в БД). Чтобы добавить сервис, разработчик:

1. Добавляет запись в `SERVICES` ([services.py](services.py)).
2. Пишет функцию-парсер в [app.py](app.py) и регистрирует её в словаре `PARSERS`.

При следующем запуске сервис автоматически появится в таблице `services` (синк `SERVICES → services`). `id` сервиса менять нельзя — он завязан на историю.

## Формат выходных файлов

### Общий Excel-отчёт

| Лист | Содержание |
|------|-----------|
| Общая сводка | Таблица ЦФО × сервисы (количество лицензий) + строка стоимости |
| User list {Сервис} | Построчно: Nickname, ЦФО |
| Pivot {Сервис} | Сводка: ЦФО → количество, %, стоимость |
| Не найдены | Ники без совпадения в справочнике |
| Доп DB {Сервис} | Вручную назначенные пользователи по сервисам |
| DB Users | Полный справочник (основной + доп.) с колонкой «Источник» |
| Для финансов | Все пользователи в формате: Продукты ТХ, Nickname, Потребитель, Единица продукта, Количество, Цена, Стоимость, Комментарий, Свободное поле |

### Отчёты по отделам (ZIP)

Для каждого ЦФО — папка с двумя файлами:

- **HTML** — отчёт с таблицей сервисов, клик по сервису раскрывает список пользователей. Итого — только стоимость.
- **XLSX** — данные в формате для финансов.

## Хранение данных

Все данные хранятся в **PostgreSQL** с привязкой к периоду. Схема — 7 таблиц (см. [schema.sql](schema.sql)):

| Таблица | Содержание |
|---------|-----------|
| `services` | Справочник сервисов (метаданные) |
| `reports` | Отчётные периоды (месяц, статус draft/finalized) |
| `report_employees` | Снимок справочника сотрудников на период |
| `report_extra_users` | Вручную назначенные пользователи на период |
| `report_prices` | Цены за лицензию на период |
| `service_uploads` | Прогресс загрузки файлов (имя файла, число строк) |
| `billing_entries` | Основные данные биллинга (ник, ЦФО, источник) |

Единственное, что хранится вне БД — выбранная тема оформления (`theme.json`), это сделано сознательно.

## Передача другому пользователю

1. Клонировать репозиторий.
2. Установить Python 3.8+ и PostgreSQL, создать пустую базу.
3. Создать `.venv`, выполнить `pip install -r requirements.txt`.
4. Скопировать `.env.example` в `.env` и указать параметры своей БД.
5. Выполнить `migrate.py` (создаст таблицы и сервисы).
6. Запустить `streamlit run app.py`.

Данные (периоды, справочники, цены) хранятся в PostgreSQL — при переносе на другую машину переносится база данных, а не файлы.
